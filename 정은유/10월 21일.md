<일주일 동안 내가 만들어 낸 것(만들어낸 것이 없으면 노력한 것, 학습한 것도 가능)>  
이번 주에는 프론트엔드 화면의 최종 UI 수정과 발표 준비를 진행하였다.

검사 상세 페이지에서 실제 발표에 사용할 노트북 환경에 맞춰 반응형 UI를 수정했다. 화면 높이가 낮은 환경에서 관리자 비고 저장 버튼이 화면 아래로 잘리는 문제가 있어 카드 높이와 내부 레이아웃을 조정하여 버튼이 정상적으로 보이도록 수정했다.

리포트 페이지에서는 전체 이상 건수를 추가하고, 기간 조회를 위한 날짜 필터와 조회 버튼, 검사 이력 버튼의 배치를 수정했다. 처음에는 검사 이력 버튼을 날짜 필터 위쪽에 배치했지만 화면의 빈 공간이 너무 넓어 보여 날짜 필터와 같은 줄에 배치하도록 변경했다.

아진산업 현장 발표를 대비하여 최종 발표 자료를 다시 확인하고 발표를 듣는 사람이 궁금해할 수 있는 예상 질문들을 정리했다. 특히 AI 정확도, AI 오판 시 처리 방법, 복합 불량 발생 가능성, 실제 현장 적용 가능 여부 등 프로젝트의 기획과 기술적인 부분에 대해 질문과 답변을 준비했다.

<일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법>  
개발 환경마다 화면 크기와 해상도가 달라 UI가 다르게 보이는 문제가 가장 어려웠다. 개발 중인 노트북에서는 정상적으로 보였지만 실제 발표에 사용할 노트북에서는 검사 상세 페이지의 일부 버튼이 잘리거나 리포트 페이지의 여백이 지나치게 크게 보이는 문제가 발생했다.

이를 해결하기 위해 특정 크기로 화면을 고정하기보다는 화면 너비와 높이에 따라 요소의 크기와 간격이 조절되도록 미디어 쿼리와 레이아웃을 수정했다. 또한 실제 발표 환경에서 화면을 직접 확인하면서 버튼 위치, 카드 높이, 필터 영역의 간격을 반복해서 조정했다.

리포트 페이지의 상단 UI도 처음에는 검사 이력 버튼을 별도의 줄에 배치했지만 전체 영역이 너무 넓어지는 문제가 있어 날짜 조회 영역과 같은 줄에 배치하여 공간을 줄였다.

<내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점>  
실제 사용 환경을 기준으로 화면을 확인하고 문제가 발생한 부분을 계속 수정한 점은 잘했다고 생각한다. 단순히 기능이 동작하는 것에서 끝내지 않고 발표 환경에서 버튼이 잘리지 않는지, 화면의 여백과 정렬이 자연스러운지까지 확인하며 UI 완성도를 높였다.

또한 발표 자료를 개발자의 관점에서만 보지 않고 프로젝트를 처음 접하는 사람이 어떤 부분을 궁금해할지 생각하며 예상 질문을 준비한 점도 잘한 부분이라고 생각한다.

아쉬웠던 점은 처음부터 다양한 화면 크기를 충분히 고려하여 UI를 구성하지 못해 발표 직전에 반응형 디자인을 여러 번 수정하게 된 것이다. 앞으로는 처음 화면을 구현할 때부터 여러 해상도에서 테스트하면서 개발하면 수정 시간을 줄일 수 있을 것 같다.

<다음주까지 해올 것>  
아진산업 현장 발표를 위해 최종 웹 화면을 다시 점검하고 발표 시 시연할 기능의 동작 여부를 확인할 예정이다.

또한 발표 자료의 내용과 실제 구현된 기능이 일치하는지 팀원들과 확인하고, AI 정확도, 재학습 방식, 불량 유형 분류, 실제 현장 적용 방법 등 예상 질문에 대한 답변을 정리할 예정이다.

발표 전에 전체 시연 과정을 반복해서 확인하여 화면 오류나 기능 문제가 발생하지 않도록 준비할 예정이다.
