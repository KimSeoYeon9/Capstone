- 백엔드 API 명세를 참고하여 실제 웹사이트에 필요한 기능과 화면을 구분하였다.

## 일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법

- 백엔드 API에 있는 기능과 실제 웹사이트에서 필요한 화면을 구분하는 것이 어려웠다.
- 모든 기능을 화면으로 만들려고 하면 프로젝트 규모가 너무 커질 수 있어, 프로젝트에 꼭 필요한 기능만 선별하여 화면을 구성하는 방향으로 정리하였다.

## 내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점

### 잘한 점

- 프로젝트의 핵심 기능을 기준으로 필요한 화면을 정리하고 불필요한 기능을 줄였다.
- 공장 작업자가 빠르게 확인해야 한다는 사용 환경을 고려하여 복잡한 화면보다는 직관적인 UI를 구성하려고 하였다.
- 백엔드 API와 UI의 관계를 확인하면서 실제 사용자에게 필요한 화면을 구분하였다.

### 아쉬웠던 점

- 아직 실제 UI 디자인까지 완성하지 못한 점이 아쉬웠다.
- 화면별 정보 배치와 디자인을 더 구체적으로 정리할 필요가 있다.

## 다음주까지 해올 것

- 프로젝트에 필요한 전체 UI 디자인을 완성한다.
- 관리자 로그인, 실시간 검사, NG 이력, NG 상세, 리포트 화면의 디자인을 구체화한다.
- 공장 현장에서 작업자가 빠르게 확인할 수 있도록 큰 글씨와 명확한 상태 표시를 활용하여 직관적인 화면을 제작한다.
- UI 명세서를 완성하고 팀원들과 화면 구성을 확인하여 수정할 부분을 정리한다.

### 시도한 것

- 회사에서 제공해주신 과제를 바탕으로 **비전 NG 사유 자동 판별 프로젝트의 UI 명세서**를 작성하였다.

- 프로젝트에서 필요한 웹 페이지를 정리하고, 각 페이지에 어떤 기능과 정보가 들어가야 하는지 구성하였다.

- 특히 작업자가 공장 현장에서 쉽게 사용할 수 있도록 복잡한 디자인보다는 필요한 정보를 한눈에 확인할 수 있는 방향으로 UI를 구성하려고 하였다.

### 실패한 것과 그 원인 분석

- UI 명세서를 제대로 작성해보는 것이 처음이라 처음에 어떤 내용을 작성해야 하는지, 각 페이지의 기능과 구성 요소를 어떻게 정리해야 하는지 몰라 시작하는 데 어려움이 있었다.

### 해결을 위해 시도한 것

- 회사에서 제공해주신 과제와 프로젝트 요구사항을 다시 확인하면서 UI 명세서에 필요한 내용을 하나씩 정리하고, 블로그를 참고하면서 어떻게 작성해야 하는지 점차 알아갔다.

- 각 페이지마다 필요한 기능과 화면에 표시되어야 하는 정보를 구분하고 실제 사용자인 공장 작업자가 쉽게 사용할 수 있는 화면을 생각하면서 명세서를 작성하였다.

### 배운점 및 추후 계획

- UI 명세서는 단순히 화면을 예쁘게 디자인하는 것이 아니라, 각 화면의 기능과 구성 요소를 구체적으로 정리하여 실제 개발에 활용할 수 있도록 만드는 문서라는 것을 배웠다.

- 처음에는 작성 방법을 몰라 어려움을 겪었지만 직접 작성해보면서 UI 명세서의 구성과 작성 방법을 익힐 수 있었다.
